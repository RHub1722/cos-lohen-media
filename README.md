# Звуковая дорожка косплей-выступления

Детерминированная сборка аудиодорожки: Python описывает сценарий, FFmpeg делает
всю обработку и сведение. Одинаковый сценарий и одинаковые исходники всегда дают
одинаковый результат.

- Итоговая длительность: **103 секунды** (01:43.000)
- Формат: **WAV, 48 kHz, stereo, PCM 24-bit**
- Громкость master: **≈ -16 LUFS**, True Peak **не выше -1.5 dB**
- Исходные WAV-файлы **только читаются** и никогда не перезаписываются

---

## 1. Как установить FFmpeg на Windows

Нужен не только `ffmpeg`, но и `ffprobe` — он входит в тот же дистрибутив.

**Способ 1 — winget (проще всего).** Откройте PowerShell и выполните:

```bash
winget install Gyan.FFmpeg
```

После установки **закройте окно PowerShell и откройте новое** — иначе PATH
останется старым и `ffmpeg` не найдётся.

**Способ 2 — вручную.**

1. Скачайте сборку с https://www.gyan.dev/ffmpeg/builds/ (вариант
   `ffmpeg-release-full.7z`).
2. Распакуйте, например, в `C:\ffmpeg`. Внутри должна быть папка `C:\ffmpeg\bin`
   с файлами `ffmpeg.exe` и `ffprobe.exe`.
3. Добавьте `C:\ffmpeg\bin` в переменную среды `PATH`:
   «Пуск» → «Изменение системных переменных среды» → «Переменные среды» →
   в разделе «Переменные среды пользователя» выберите `Path` → «Изменить» →
   «Создать» → вставьте `C:\ffmpeg\bin` → OK.
4. Откройте новое окно PowerShell.

Также нужен **Python 3.11 или новее** — https://www.python.org/downloads/windows/
При установке включите галочку **«Add python.exe to PATH»**.

Внешних Python-пакетов проект не требует: используется только стандартная
библиотека (см. `requirements.txt`).

## 2. Как проверить командой ffmpeg -version

```bash
ffmpeg -version
```

Должна появиться строка вида `ffmpeg version 8.1.1-full_build-...`. Проверьте
заодно остальное:

```bash
ffprobe -version
```

```bash
python --version
```

Если какая-то команда пишет «не распознана как имя командлета» — программа не в
`PATH`. Вернитесь к разделу 1 и не забудьте открыть **новое** окно PowerShell.

Полную проверку окружения, папок и всех WAV-файлов делает валидатор:

```bash
python src/validator.py
```

## 3. Куда класть голоса

Голосовые файлы кладутся в `assets/voices/` **с точно такими именами**:

| Файл | Начало | Роль |
|---|---|---|
| `auctioneer_intro.wav` | 00:00.000 | вступление аукциониста |
| `buyer_suspicious.wav` | 00:20.000 | подозрительный покупатель (панорама слегка влево) |
| `lohen_notice.wav` | 00:29.000 | Лоэн замечает (по центру) |
| `auctioneer_sold.wav` | 00:40.000 | «продано» |
| `lohen_reveal.wav` | 00:48.000 | раскрытие |
| `lohen_final_question.wav` | 01:20.000 | финальный вопрос |
| `lohen_final_line.wav` | 01:29.000 | финальная реплика |

Требования к файлам: WAV, желательно 48 kHz stereo. Другую частоту или моно
сборка тоже примет — приведёт сама и напишет предупреждение.

Какие голоса ElevenLabs использовать для каждого персонажа, с какими тегами
подачи и как разрезать многоспикерную выгрузку на отдельные файлы —
[docs/elevenlabs-voices.md](docs/elevenlabs-voices.md).

**Пока файла нет, событие просто пропускается** с понятным предупреждением, а
сборка продолжается. Все отсутствующие файлы перечислены в конце вывода и в
`output/render-report.json` в разделе `missing_optional_assets`.

Длительность реплики задавать не нужно — она берётся из самого файла. Как только
файл появится, автоматически включится и приглушение фона под ним (см. раздел 7).

Для `auctioneer_intro.wav` в сценарии указан ожидаемый слот реплики
00:08.000–00:20.000: если файл окажется длиннее и выйдет за 00:20.000 (там
начинается следующая реплика), валидатор предупредит.

## 4. Как изменить таймкоды

Все таймкоды, уровни, панорамы и пути лежат в одном файле —
[`scenario/timeline.json`](scenario/timeline.json). **Код менять не нужно.**

Формат времени — `"MM:SS.mmm"`, например `"01:29.000"`. Можно писать и просто
число секунд (`89.0`).

**Сдвинуть событие.** Поменяйте `start` (и `end`, если он задан):

```json
{ "id": "auction_gavel", "start": "00:40.500" }
```

**Изменить громкость по времени.** `volume_points` — это ключевые точки
огибающей в dB, между ними значение меняется линейно:

```json
"volume_points": [
  { "t": "00:00.000", "db": -25.0 },
  { "t": "00:57.000", "db": -25.0 },
  { "t": "01:10.000", "db": -22.0 }
]
```

**Изменить громкость целиком.** Для одиночных звуков используется постоянный
`gain_db` (например, `-6.0` у молотка).

**Панорама.** `pan` от `-1.0` (влево) до `1.0` (вправо), `0.0` — центр.
Панорама только ослабляет дальний канал и никогда не поднимает уровень выше
исходного, поэтому не может привести к клиппингу.

Полезные поля события:

| Поле | Значение |
|---|---|
| `id` | уникальный идентификатор (дубликаты валидатор не пропустит) |
| `stem` | категория: `ambience`, `voices`, `sfx` или `music` |
| `file` | путь **относительно корня проекта** |
| `start` / `end` | окно события; без `end` длительность берётся из файла |
| `required` | `true` — без файла сборка остановится; `false` — пропустит с предупреждением |
| `loop` | `true` — длинный фон зацикливается бесшовным кроссфейдом |
| `duck_group` | `ambience`, `crowd` или `null` — насколько приглушать под голосами |
| `gain_db` | постоянная громкость |
| `volume_points` | автоматизация громкости по таймкодам |
| `pan` | панорама от -1.0 до 1.0 |
| `pan_points` | автоматизация панорамы по таймкодам; перебивает статический `pan` |
| `fade_in` / `fade_out` | короткие фейды в секундах (0.005-0.02) против щелчков |
| `trim_silence` | `true` — обрезать тишину по краям исходника (замер на сборке) |
| `width` | расширение стереобазы: 1.0 — как есть, 1.3 — шире |
| `swap_channels` | `true` — поменять каналы местами |
| `ducks` | это событие само приглушает указанные группы (акцент расчищает фон) |
| `normalize_source` | `true` — dB читаются как абсолютный уровень, а не как ослабление (см. ниже) |

Общие настройки в том же файле:

- `total_duration` — общая длительность (сейчас 103 секунды);
- `output` — частота, разрядность, целевые LUFS и True Peak;
- `loop.crossfade` — длина кроссфейда при зацикливании (0.4 с);
- `ducking` — глубина приглушения, атака и release;
- `transition` — переход «зал → замороженный зал» около 01:29.

После правки проверьте файл, не запуская рендер:

```bash
python src/build.py --validate-only
```

## 5. Как запустить сборку

```bash
python src/build.py
```

Или через PowerShell из корня проекта:

```bash
.\build.ps1
```

`build.ps1` дополнительно проверяет версию Python и наличие FFmpeg, а все
аргументы передаёт дальше без изменений.

Аргументы:

| Аргумент | Что делает |
|---|---|
| `--scenario <путь>` | другой файл сценария (по умолчанию `scenario/timeline.json`) |
| `--no-normalize` | не приводить громкость к -16 LUFS, оставить только лимитер True Peak |
| `--verbose` | показывать все команды ffmpeg и их вывод |
| `--validate-only` | только проверки, без рендера |
| `--output <папка>` | другая папка для результатов (по умолчанию `output`) |
| `--output-suffix v2` | суффикс имён результатов. Без аргумента берётся `output.default_suffix` из сценария; `--output-suffix ""` собирает без суффикса |
| `--mp3` | дополнительно сохранить MP3 320 kbps для быстрого прослушивания |
| `--keep-intermediate` | не удалять промежуточный микс `output/_premaster.wav` |

Примеры:

```bash
python src/build.py --scenario scenario/timeline.json
```

```bash
python src/build.py --no-normalize
```

```bash
python src/build.py --verbose
```

Текущая рабочая команда для черновика с боевой сценой:

```bash
python src/build.py --output-suffix v2 --mp3
```

### Каждый сценарий называет свои результаты сам

У `scenario/timeline.json` в блоке `output` стоит `"default_suffix": "v2"`,
поэтому `python src/build.py` без аргументов собирает `master_v2.wav` и не
трогает файлы прежней версии. У резервной копии этого поля нет — она собирается
в `master.wav`. Так два сценария не затирают друг друга:

```bash
python src/build.py --scenario scenario/backups/timeline-v1.json
```

Резервные копии сценариев лежат в `scenario/backups/` и не перезаписываются.

## 6. Где искать результат

Всё складывается в `output/`:

| Файл | Что это |
|---|---|
| `master.wav` | итоговая дорожка: 103 с, 48 kHz, stereo, PCM 24-bit, ≈ -16 LUFS |
| `ambience.wav` | stem: акустика зала, гул толпы, замороженный зал |
| `voices.wav` | stem: реплики |
| `sfx.wav` | stem: шёпот, щелчок оков, молоток, вздох толпы |
| `music.wav` | stem: музыка |
| `render-report.json` | полный отчёт: что вошло, чего не хватило, замеры громкости |
| `ffmpeg-command.txt` | все выполненные команды ffmpeg — можно перезапустить вручную |

Папка `output/` под версионным контролем: WAV, MP3 и отчёты коммитятся вместе
с проектом, чтобы к любой прошлой сборке можно было вернуться, не пересобирая
её. Исключён только промежуточный микс `_premaster*.wav`.

Пустая категория всё равно даёт корректный stem — 103 секунды тишины в нужном
формате. Сейчас так собираются `voices.wav` (нет голосов) и `music.wav`
(папка `assets/music` пуста).

Что смотреть в `render-report.json`:

- `missing_optional_assets` — какие файлы не найдены и где они ожидались;
- `loudness.measured_after` — фактические LUFS и True Peak готового master;
- `loudness.normalization_type` — `linear` (динамика сценария сохранена) или
  `dynamic` (loudnorm её переформовал);
- `events[].level` — уровень исходника, компенсация и расчётный уровень
  события в миксе (см. про две шкалы громкости ниже);
- `events[].envelope_db` — итоговая огибающая каждого события в абсолютном
  времени, уже с учётом приглушения; удобно сверять с задумкой;
- `stems[].peak_dbfs` — пик каждого stem;
- `ducking.voice_windows` — интервалы, в которые звучат голоса;
- `render_warnings` — все предупреждения последней сборки.

### Две шкалы громкости: `normalize_source`

По умолчанию `gain_db` и `volume_points` — это **относительное ослабление
исходника**. У файлов собственные уровни различаются примерно на 40 dB, поэтому
одинаковая добавка даёт совершенно разную слышимость. С флагом
`"normalize_source": true` исходник сначала приводится к пику 0 dBFS, и те же
значения читаются как **абсолютный целевой уровень**.

| Событие | Исходник | Шкала | Сценарий | В миксе |
|---|---|---|---|---|
| `auction_gavel` | -16.2 dBFS | абсолютная | -6.0 dB | **-15.6 dBFS** |
| `metal_restraint_click` | -0.1 dBFS | абсолютная | -12.0 dB | **-21.6 dBFS** |
| `crowd_gasp` | 0.0 dBFS | абсолютная | -13.0 dB | **-22.6 dBFS** |
| `frozen_hall` | 0.0 dBFS | относительная | -21.0 dB | **-21.0 dBFS** |
| `crowd_suspicious_whispers` | -31.4 dBFS | абсолютная | -24.0 dB | **-33.6 dBFS** |
| `hall_room` | -17.5 dBFS | относительная | -22.0 dB | **-39.5 dBFS** |
| `crowd_murmur` | -26.4 dBFS | относительная | -25.0 dB | **-51.4 dBFS** |

Все четыре SFX стоят на абсолютной шкале, поэтому их взаимный баланс ровно
такой, как в задании: молоток громче щелчка на 6.0 dB, щелчок громче вздоха на
1.0 dB. Фон оставлен на относительной шкале намеренно — так он звучит тише
ударов, что и требуется.

**Запас `mix.absolute_headroom_db`.** Абсолютная шкала ставится не в 0 dBFS, а
на 9.6 dB ниже. Без этого запаса удары упираются в потолок True Peak при
нормализации master, лимитер расплющивает их в один уровень, и заданный баланс
до готового файла не доживает (замерено: все три удара выходили ровно на
-1.80 dBFS). Сдвиг общий для всех таких событий, поэтому баланс между ними не
меняется, а значения в сценарии остаются такими же, как в задании.

Сборка предупреждает, если расчётный пик события ниже -55 dBFS (почти не слышно)
или выше -1 dBFS (риск упереться в потолок). Всё правится в
`scenario/timeline.json`, код менять не нужно.

## 7. Как заменить отдельный звук без изменения кода

Есть два способа, оба не требуют правки Python.

**Способ 1 — положить файл с тем же именем.** Самый быстрый: замените файл в
`assets/`, сохранив имя, и запустите сборку заново. Длительность может быть
любой — сборка сама подгонит:

- файл **длиннее** окна события — обрежется;
- файл **короче** и `loop: true` — зациклится бесшовным кроссфейдом;
- файл **короче** и `loop: false` — остаток дополнится тишиной (с предупреждением).

**Способ 2 — указать другой путь в сценарии.** Откройте
`scenario/timeline.json`, найдите событие по `id` и поменяйте `file`:

```json
{
  "id": "auction_gavel",
  "file": "assets/ambience/alternatives/auction_gavel.wav",
  "gain_db": -6.0
}
```

Так удобно перебирать варианты из `assets/ambience/alternatives/`, не удаляя
основные файлы. Путь всегда относительный от корня проекта.

Если нужно **временно выключить** звук — поставьте событию несуществующий путь
и `"required": false`: оно будет пропущено с предупреждением и попадёт в
`missing_optional_assets`.

## Как это устроено

Микширование целиком на FFmpeg, `pydub` и другие тяжёлые зависимости не
используются. Python считает числа и собирает `filter_complex`.

**Зацикливание фонов.** Никакого «тупого» повторения с резким стыком: файл
подаётся на вход нужное число раз, копии склеиваются `acrossfade` длиной 0.4 с с
кривой `qsin` (equal-power). Число копий считается с учётом того, что каждый
кроссфейд «съедает» 0.4 с: `N*dur - (N-1)*0.4`. Для зала это 3 копии по 30 с =
89.2 с, что покрывает нужные 88.85 с.

**Автоматизация громкости.** У каждого события одна огибающая, линейная в dB
между ключевыми точками. Она превращается в выражение для фильтра `volume`
с `eval=frame`. Перед ним стоит `asetnsamples=n=128`, чтобы огибающая
пересчитывалась каждые ~2.7 мс — иначе на 80 мс атаке слышны ступеньки.

**Обрезка тишины и фейды.** У one-shot эффектов тишина по краям меряется на
сборке через `silenceremove` — по убыли длительности, а не разбором парных
событий `silencedetect` (так надёжнее). Пороги разные: -50 dB в начале и -60 dB
в конце, потому что при одинаковом пороге срезался бы естественный хвост
реверберации. Каждое событие получает фейды 5-20 мс, чтобы обрезка не давала
щелчка. Замерено: существенная тишина есть только у `crowd_fleeing_distant`
(130 мс в начале и 1000 мс в конце), у `ice_resonance_tail` хвост идёт до
последнего сэмпла и не трогается.

**Панорама в движении.** Фильтр `pan` умеет только постоянные коэффициенты,
поэтому автоматизация делается раздельной обработкой каналов:
`channelsplit` → два `volume` с выражениями → `join`. Проверено на центрированном
тоне: R-L идёт от +3.7 dB через ноль к -4.1 dB.

Отдельный случай — `swap_channels`. У `bullet_pass_close.wav` собственное
движение панорамы уже записано в файл, причём слева направо: замер даёт R-L от
-2 dB к +25 dB. Автоматизация баланса даёт максимум ±4.4 dB и перебить такой
встроенный образ не может, поэтому каналы меняются местами. После этого пролёт
пули идёт справа налево, как задумано (замерено: +5.7 → -25.5 dB).

**Приглушение: два источника.** Помимо реплик фон расчищают акценты — выстрел и
ледяной удар. У события есть поле `ducks` с явным окном (`pre` до начала,
`hold` после) и собственной глубиной. Окно задаётся явно, а не длиной файла: у
выстрела длинный реверб-хвост, и держать фон приглушённым все 2 секунды не
нужно. Проверено сравнением двух сборок: внутри окна выстрела фон ровно
-2.50 dB, перед ледяным ударом -2.97 dB, вне окон 0.00 dB.

**Приглушение под голосами (ducking).** Сайдчейн-компрессия не используется:
длительности реплик читаются через `ffprobe`, интервалы голосов объединяются, и
приглушение считается заранее как смещение той же dB-огибающей — атака 80 мс,
release 300 мс, глубина -6 dB для `ambience` и -8 dB для `crowd`. Результат
полностью предсказуем и виден в `render-report.json`.

**Громкость master.** Двухпроходный `loudnorm`, затем `aresample` (фильтр
`loudnorm` работает внутри на 192 kHz) и лимитер.

Важная деталь: `linear=true` — это **просьба, а не гарантия**. `loudnorm`
применяет один постоянный коэффициент только пока прирост укладывается в
потолок True Peak. Иначе он молча переключается на динамическую нормализацию и
переформовывает динамику — тихие места поднимаются сильнее громких. Сборка
читает его собственный отчёт и пишет фактический режим в
`render-report.json` → `loudness.normalization_type`, а при переключении на
`dynamic` выводит предупреждение.

Отсюда два режима, оба замерены на текущем черновике:

| | `preserve_dynamics: true` (выбрано) | `preserve_dynamics: false` |
|---|---|---|
| Громкость master | -18.6 LUFS | **-16.7 LUFS** |
| True Peak | -2.30 dB | -1.80 dB |
| Режим loudnorm | `linear` | `dynamic` |
| Прирост по дорожке | постоянный +13.3 dB | гуляет +14.3…+19.8 dB |
| Уровни сценария | сохранены точно | частично переформованы |

Сейчас выбрана **динамика**: уровни -25/-22/-30 dB и баланс SFX доходят до файла
без изменений, тишина боевой паузы 00:57-01:20 остаётся тишиной. Замерено —
прирост на всей дорожке лежит в пределах +13.29…+13.38 dB.

Плата за это — громкость на 2.6 dB ниже цели -16 LUFS. Для живого выступления
абсолютный уровень всё равно ставит пульт; если понадобится именно -16 LUFS
(например, для публикации записи), поставьте `output.preserve_dynamics: false`.

Предел линейного режима считается просто: `потолок True Peak - crest микса`.
У текущего черновика crest 16.3 dB, потолок -1.8 dB, отсюда около -18.1 LUFS.
Когда добавятся голоса, микс станет плотнее, crest уменьшится, и линейный режим
дотянет ближе к -16 LUFS сам.

Здесь есть один нюанс, о котором стоит знать. Требование -16 LUFS рассчитано на
готовый микс. Пока голосов нет, дорожка состоит из тихого фона, и буквальная
нормализация подняла бы фон зала неестественно громко. Поэтому прирост ограничен
`output.max_normalize_gain_db` (по умолчанию 14 dB): если до цели не хватает
больше, сборка выведет предупреждение и запишет в `render-report.json` и
запрошенный, и фактически применённый прирост. На текущем черновике микс
измеряется как -28.9 LUFS, нужно +12.9 dB — ограничение не срабатывает, и
master выходит ровно на -16.0 LUFS. Когда добавятся голоса, микс станет громче,
и запас тем более не понадобится.

**Защита от клиппинга.** Промежуточный микс делается в float32, `amix` идёт с
`normalize=0` (уровни задаёт сценарий, а не делитель), True Peak ограничивается
с запасом `output.true_peak_margin_db` = 0.3 dB, чтобы замер гарантированно
оказался не выше -1.5 dB. Пик каждого stem измеряется и попадает в отчёт;
если что-то подходит к 0 dBFS, сборка предупредит.

**Переход в 01:29.** В сценарии `fade_end` = 01:28.850 и `gap_ms` = 150:
акустика зала и гул толпы затухают к 01:28.850, затем 150 мс полной тишины, и
ровно в 01:29.000 вступает `frozen_hall_ambience.wav`. Валидатор проверяет, что
пауза действительно есть.

**Боевая сцена 00:57–01:20** пока не наполнена: фон зала и толпы продолжает
звучать, никаких ударов, музыки и криков не добавляется. Папки
`assets/combat`, `assets/ice` и `assets/music` пусты.

## Если что-то не работает

**«FFmpeg не найден в PATH».** Проверьте `ffmpeg -version` в **новом** окне
PowerShell. См. раздел 1.

**«Требуется Python 3.11 или новее».** Проверьте `python --version`. Если стоит
несколько версий, попробуйте `py -3.12 src/build.py`.

**Кракозябры вместо русского текста.** Вывод переводится в UTF-8
автоматически. Если символы всё же ломаются, выполните `chcp 65001` перед
сборкой или запускайте через Windows Terminal.

**Сборка остановилась с ошибкой.** Ошибки перечислены в конце вывода, а все
команды ffmpeg сохранены в `output/ffmpeg-command.txt` — любую можно
перезапустить вручную из корня проекта и посмотреть полный вывод. Ещё подробнее:

```bash
python src/build.py --verbose
```

**Результат звучит не так, как ожидалось.** Посмотрите
`events[].envelope_db` в `output/render-report.json` — там итоговая огибающая
каждого события в абсолютном времени, уже с приглушением. Это самый быстрый
способ понять, что именно применилось.

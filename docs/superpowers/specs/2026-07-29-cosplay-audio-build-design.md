# Детерминированная сборка звуковой дорожки — дизайн

Дата: 2026-07-29

## Задача

Локальный Python-проект, который собирает 103-секундную звуковую дорожку к
косплей-выступлению из WAV-ассетов. Python описывает сценарий, FFmpeg делает всю
обработку. Исходные файлы только читаются.

Формат результата: WAV, 48 kHz, stereo, PCM 24-bit, master ≈ -16 LUFS,
True Peak ≤ -1.5 dB, без клиппинга. Отдельные stems: ambience, voices, sfx,
music.

Ограничения: без `pydub`, без тяжёлых зависимостей, все пути относительны корня
проекта, Python 3.11+.

## Состояние ассетов на момент проектирования

Все 7 файлов фона и SFX присутствуют, 48 kHz stereo PCM 16-bit. Голосов нет ни
одного — папка `assets/voices` пуста. `assets/music`, `assets/combat`,
`assets/ice` пусты.

## Принятые решения

### Зацикливание — цепочка acrossfade

Файл подаётся на вход `N` раз (отдельными `-i`, не через `asplit` — надёжнее по
буферизации), копии склеиваются `acrossfade=d=0.4:c1=qsin:c2=qsin`. `qsin` —
equal-power. Число копий: `ceil((need - xf) / (dur - xf))`, потому что каждый
кроссфейд «съедает» `xf` секунд. Для зала — 3 копии по 30 с = 89.2 с при
нужных 88.85 с.

### Автоматизация громкости — одно выражение volume

Одна огибающая на событие, линейная в dB между ключевыми точками, компилируется
в выражение `volume='if(lt(t,T),...)':eval=frame`.

Рассмотренная альтернатива — цепочка `afade`. Отклонена: `afade` умеет только
фейды в тишину и из тишины, а сценарию нужны произвольные переходы между
уровнями (-25 → -22 → -30).

`eval=frame` пересчитывает выражение раз в кадр. При кадре по умолчанию
(~1024 сэмпла = 21 мс) на 80 мс атаке получилось бы 4 ступеньки — слышен
зиппер. Поэтому перед `volume` стоит `asetnsamples=n=128` — пересчёт каждые
2.7 мс. `eval=sample` фильтр `volume` не поддерживает.

### Ducking — предрасчёт, не sidechain

ТЗ разрешает предрасчёт, если боковая компрессия ненадёжна. Выбран предрасчёт:
длительности реплик читаются через `ffprobe`, интервалы объединяются, приглушение
превращается в смещение той же dB-огибающей (атака 80 мс, release 300 мс,
глубина -6 dB для `ambience`, -8 dB для `crowd`).

Ключевая деталь: и базовая огибающая, и кривая приглушения кусочно-линейны в dB,
поэтому их сумма на объединённом наборе изломов вычисляется **точно** — не
приближённо. При нескольких активных репликах берётся самое глубокое
приглушение (`min`).

Плюс подхода: результат полностью предсказуем, виден в отчёте и не зависит от
поведения детектора компрессора.

### Панорама — только ослабление

`pan < 0` → `L=1.0, R=1+pan`; `pan > 0` → `L=1-pan, R=1.0`. Константная мощность
(`sqrt(2)*cos`) отклонена: она поднимает ближний канал выше единицы и создаёт
риск клиппинга. При `pan=0` фильтр вообще не добавляется.

### Защита от клиппинга

Промежуточный микс во float32 (PCM не может превысить 0 dBFS, float может —
клиппинг переносится на финальный лимитер). `amix` с `normalize=0`: уровни
задаёт сценарий, а не делитель на число входов. True Peak ограничивается с
запасом 0.3 dB, иначе `loudnorm` промахивается на сотые вверх и формально
нарушает -1.5 dB.

### Громкость master — двухпроходный loudnorm с ограничением прироста

После `loudnorm` обязателен `aresample=48000`: фильтр работает внутри на 192 kHz.

**Уточнение после замеров (первая версия документа была неверна).**
`linear=true` — просьба, а не гарантия. `loudnorm` остаётся линейным только при
двух условиях одновременно: `measured_TP + прирост <= target_TP` и
`measured_LRA <= target_LRA`. Иначе он молча уходит в динамический режим и
переформовывает динамику. На черновике это и происходило: прирост гулял от
+14.3 до +19.8 dB, тихая боевая пауза раздувалась на 13.6 dB сильнее громких
мест — ровно то, чего требовалось избежать.

Теперь сборка читает `normalization_type` из отчёта самого `loudnorm`, пишет его
в `render-report.json` и предупреждает при переключении на `dynamic`.

Добавлен флаг `output.preserve_dynamics`. При `true` прирост ограничивается так,
чтобы режим остался линейным. Две детали, обе выяснены замером:

* нужен отступ 0.5 dB — ровно на границе `<=` проваливается на округлении float,
  и режим молча становится динамическим;
* целевой LRA поднимается выше измеренного, иначе `loudnorm` уходит в динамику,
  чтобы сузить диапазон, — а сужать его здесь не нужно.

Достижимая в линейном режиме громкость равна `потолок True Peak - crest микса`.
У черновика crest 16.3 dB, потолок -1.8 dB, отсюда предел около -18.1 LUFS.
Требования «-16 LUFS», «TP <= -1.5 dB» и «сохранить динамику» для этого
материала одновременно невыполнимы — любые два из трёх.

Требование -16 LUFS рассчитано на готовый микс. Пока голосов нет, дорожка — это
тихий фон, и буквальная нормализация подняла бы фон зала неестественно громко.
Поэтому прирост ограничен `max_normalize_gain_db` = 14 dB с явным
предупреждением и записью запрошенного и применённого прироста в отчёт.

Фактически на этом черновике микс измерился как -28.9 LUFS, потребовалось
+12.9 dB — ограничение не сработало, master вышел ровно на -16.0 LUFS.

### Переход в 01:29

ТЗ содержит противоречие: fade-out зала «закончить в 01:29» и одновременно
«оставить паузу примерно 150 мс» перед замороженным залом. Решение (согласовано
с заказчиком): затухание заканчивается в **01:28.850**, далее 150 мс тишины,
`frozen_hall_ambience` вступает ровно в **01:29.000**. Это сохраняет сетку
01:29–01:43 = 14 с, указанную в ТЗ дважды. Значения вынесены в
`transition.fade_end` и `transition.gap_ms`, валидатор проверяет наличие паузы.

### auctioneer_intro

ТЗ задаёт старт 00:00.000 и одновременно «примерный слот реплики
00:08.000–00:20.000». Взят буквальный `start: 00:00.000`, а слот записан в
`slot_hint`: когда файл появится, валидатор предупредит, если реплика выйдет за
00:20.000, где начинается следующая.

## Проверка

Помимо сборки проверены:

- огибающие: сгенерированное выражение сверено с намерением в 4000 точках,
  максимальное расхождение 0.004 LSB 24-битного кванта (< 0.000001 dB);
- ducking в готовом WAV: база -69.08 dB, полное приглушение -75.08 dB
  (ровно -6.00), достигается к +80 мс, восстанавливается к +300 мс;
- `gain_db`: замер -24.999 dB при заданных -25;
- пауза 01:28.850–01:29.000: `Peak level dB: -inf`, то есть точный ноль;
- стыки петли: пик производной сигнала на стыках (-65.3 и -58.3 dB) **ниже**,
  чем в контрольных окнах (-50.3, -60.5, -55.0) — разрыва нет;
- все 5 WAV: ровно 103.000000 с, pcm_s24le, 48000 Гц, 2 канала;
- master: -16.0 LUFS, True Peak -1.76 dB.

### Две шкалы громкости — normalize_source

dB в задании — относительное ослабление, а собственные уровни файлов расходятся
на ~40 dB, поэтому задуманный баланс не воспроизводился. Добавлен флаг
`normalize_source`: исходник приводится к пику 0 dBFS, и те же значения читаются
как абсолютный целевой уровень. Значения задания остаются в сценарии дословно, а
при замене WAV компенсация пересчитывается сама.

Все четыре SFX переведены на абсолютную шкалу; фон оставлен на относительной
намеренно — так он тише ударов, как и требуется.

Отклонённая альтернатива: перевести на абсолютную шкалу **все** события. Замер
показал, что это хуже — фон поднимается, но интегральная громкость микса
падает с -29.8 до -35.3 LUFS. Причина в гейтированном измерении: `frozen_hall`
ярче по спектру, K-взвешивание это учитывает, и добавление 89 секунд глухого
фона снижает гейтированное среднее. Прирост упирался в кап, master выходил на
-20.8 LUFS.

### Запас mix.absolute_headroom_db

Абсолютная шкала ставится на 9.6 dB ниже 0 dBFS. Без запаса удары упираются в
потолок True Peak при нормализации master: замер показал, что молоток, щелчок и
вздох выходили ровно на -1.80 dBFS, то есть выставленный баланс не доживал до
готового файла. Сдвиг общий, поэтому баланс между событиями не меняется.

По той же причине `max_normalize_gain_db` = 14 работает как две защиты: не
раздувать почти тихий черновик и не загонять микс глубоко в лимитер. Замерено:
при 14 dB разрыв молоток-щелчок 5.8 dB (в задании 6.0) и master -16.7 LUFS; при
25 dB разрыв падает до 3.4 dB, а master уходит на -14.9 LUFS.

## Замечание о балансе

Значения dB в ТЗ — относительное ослабление исходника. Собственные уровни
файлов различаются примерно на 40 dB, поэтому задуманный баланс не
воспроизводится автоматически. Наиболее заметно:

- `crowd_suspicious_whispers` (пик -31.4 dBFS) при -24 dB даёт -55.4 dBFS —
  практически не слышно, хотя ТЗ просит «максимум -24 dB»;
- `auction_gavel` (пик -16.2 dBFS) при -6 dB даёт -22.2 dBFS, тогда как
  `metal_restraint_click` (пик -0.1 dBFS) при -12 dB даёт -12.1 dBFS — щелчок
  оков получается на 10 dB громче молотка, хотя удар должен быть «отчётливым»;
- `frozen_hall` (пик 0.0 dBFS) при -21 dB даёт -21.0 dBFS против -39.5 dBFS у
  зала — на переходе 01:29 уровень подскакивает примерно на 18 dB.

Значения из ТЗ не изменялись. Вместо этого сборка считает ожидаемый уровень
каждого события (`events[].level` в отчёте) и предупреждает, если событие
окажется ниже -55 dBFS или выше -1 dBFS. Решение о правке уровней — за
заказчиком, правится только `scenario/timeline.json`.

## Отложено

Боевая сцена 00:57–01:20 — место зарезервировано, фон продолжает звучать,
никаких ударов, музыки и криков не добавляется. Категория `music` собирается как
корректный stem из 103 с тишины.

## 1. Результаты сборки теперь в git

`output/` больше не исключается. Коммитятся WAV, MP3 и отчёты — к любой прошлой
сборке можно вернуться, не пересобирая её и не имея под рукой той же версии
FFmpeg. Заодно это страхует от случайной перезаписи.

Добавлено 15 файлов, 286.9 МБ на диске. В упакованном виде `.git` вырос с 71 до
**157 МБ**: тишина и ровный фон хорошо сжимаются, а `voices.wav`, `music.wav` и
их v2-варианты байт-идентичны (103 секунды тишины) и хранятся одним объектом.

Исключённым остаётся только промежуточный микс `_premaster*.wav` — рабочий файл
на ~79 МБ, появляется лишь при `--keep-intermediate`. Плюс подпапки временных
прогонов вида `output/_проба`.

**О чём стоит знать.** Сборка детерминирована, поэтому повторный прогон без
изменений сценария даёт те же файлы и новых объектов в git не появляется. Но
каждое изменение сценария добавляет до шести новых блобов по 28 МБ — это
`master`, `ambience`, `sfx` в обеих версиях. Три-четыре итерации подряд, и
репозиторий подойдёт к 1 ГБ, который GitHub считает границей рекомендуемого.
Если начнёт мешать, стандартный ответ — Git LFS для `output/**.wav`.

### 2.3. Запуск без суффикса больше не перезаписывает прежнюю версию

Добавлено поле `output.default_suffix`: каждый сценарий объявляет имена своих
результатов сам.

| Команда | Что собирает |
|---|---|
| `python src/build.py` | `master_v2.wav` — суффикс из `output.default_suffix` в `timeline.json` |
| `python src/build.py --scenario scenario/backups/timeline-v1.json` | `master.wav` — у бэкапа поля нет |
| `python src/build.py --output-suffix ""` | `master.wav` принудительно |
| `python src/build.py --output-suffix v3` | `master_v3.wav` |

Аргумент командной строки перебивает сценарий. Различаются «не передан» и
«передан пустым», поэтому осознанная сборка без суффикса возможна. Старый способ
запуска не сломан — §16 выполняется.
